Why a cache?

Main memory is big but slow; the CPU is fast but needs data now. A cache is a small, fast memory that keeps copies of recently used blocks so that most accesses are served in a few cycles instead of dozens. It works because programs show temporal locality (what you used recently, you’ll likely use again) and spatial locality (data near what you just used is likely next). A hit means the block is already in the cache; a miss means it must be fetched from main memory, and possibly evict an existing block to make room.

How an address is split

Every memory address is carved into three fields. From the right: the offset selects a byte inside the block, the index selects which set of the cache to look in, and whatever remains is the tag, stored alongside the data so the cache can tell blocks apart.

The three mapping schemes

Direct mapped

Each memory block can live in exactly one line: line = block mod (number of lines). Cheapest to build and fastest to check, but two hot blocks that share a line keep kicking each other out — a conflict miss.

Set associative

The cache is grouped into sets of k lines (k-way). A block maps to one set but may sit in any way within it: set = block mod (number of sets). On a miss with a full set, the replacement policy picks the victim. The sweet spot used by real CPUs.

Fully associative

A block may go in any line — there is only one set, so the index field disappears and the address is just tag + offset. No conflict misses, but every line’s tag must be compared in parallel, which is expensive hardware. Used for small structures like TLBs.

Replacement policies

When a set is full and a new block arrives, one resident block must go. The simulator implements all three classics:

  • LRU — evict the block untouched for the longest time. Best exploits temporal locality; needs usage tracking per line.
  • FIFO — evict the block that was loaded earliest, regardless of how recently it was used. Simpler hardware, slightly worse hit rates.
  • Random — pick any resident block. Surprisingly competitive, and immune to pathological access patterns.

Note that a direct-mapped cache has no choice to make — the incoming block’s one legal line is always the victim.

Reading the misses

The log labels each miss. A cold (compulsory) miss is the first-ever access to a block — unavoidable. Any later miss means the block was in the cache once and got evicted: either a conflict miss (another block mapped onto it) or a capacity miss (the working set simply doesn’t fit). Try the “Conflict thrash” demo under direct mapping, then re-run it 2-way — the misses vanish. That single comparison is the whole argument for associativity.
